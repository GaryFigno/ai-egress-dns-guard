# 用证据验证隔离

记录时间、实际版本与保护对象，备份必要配置，保留活跃工作。参数和原始证据只私下保存在本机，不能进入公开仓库。

## 实际进程与出口

识别主程序、网络辅助进程、Code引擎和工具的 PID、出生时间、路径，避免 PID复用、短暂启动器或同名程序误判。只查询本次审计相关连接。

把系统 TCP源端口与控制器的入站源端口、域名和实际链路关联。普通 curl代理成功只能证明 curl的路径，不能证明 Desktop使用相同路径。

优先使用应用已有、有界、经过验证的诊断入口。不要构造认证回调、替换业务会话或安装临时注入。没有诊断入口时结合真实连接和系统边界证据，明确未直接验证的部分。

尽量同时证明：应用连接了允许的本地入口、控制器显示指定链路、外部端点观察到预期出口。组名称或单张出口截图不能替代完整关联。

## DNS、包与事件

检查有效解析策略后，用随机标记的新查询避免缓存。正查询要有成功响应；负查询要确认实际 NXDOMAIN状态。不能把超时或 `ENOTFOUND` 一概当作隔离成功。

在明确起止时间的有界抓包中检查相关物理网卡，记录接口/组件映射、方向、过滤器与事件丢失。只抓虚拟接口不能证明物理出口没有泄露。

零 DNS抓包需要正控制：同一时间窗口确实捕获到批准出口的双向流量，并确认新查询的客户端、解析器与响应状态。UDP发送回调只证明排队成功，不证明实际出网。

同时考虑传统 DNS、DoT、DoQ、自带 DoH和 IPv6。没有明文 DNS仅证明观察窗口及协议范围；未授权 DoH仍可能藏在 HTTPS里，还要结合有效配置、应用策略与真实加密解析链路。

外部 DNS测试只能补充证据。递归解析器IP不必等于代理出口IP；Anycast或地理库可能使地区标签不一致，不能只凭国旗或“完美”评分判断。

## 故障矩阵

| 故障 | 需要验证 | 常见误判 |
| --- | --- | --- |
| 指定节点拒绝连接 | 受保护请求失败，不切换节点或直连 | 只看组内没有备用名称 |
| 节点从订阅消失 | 空组或生成策略明确拒绝 | 自动选另一节点 |
| 本地代理入口不可用 | 应用失败，直接外连仍被系统拒绝 | 把临时分区当成全局退出测试 |
| DNS上游不可用 | 查询失败，不转未批准解析器 | 把缓存回答当作安全 |
| TUN关闭、代理退出、网络切换 | 独立边界仍有效，或明确未测 | 以节点故障结果代替 |
| 升级或新工具启动 | 新路径首次联网前受保护 | 只检查旧版本 |

优先在独立实例模拟故障，再验证恢复。真实共享服务中断需要独立恢复路径及对活跃工作影响的授权。不同故障不能相互替代证明。

## IPv6、UDP、WebRTC

IPv6 `ENETUNREACH` 只表示当时不可达；IPv4 `EACCES` 等拒绝结果也要结合有效规则和代理成功正控制判断。

检查 WebRTC/STUN公网候选只呈现允许出口或没有公网候选；同时核对禁用非代理UDP的有效参数和应用约束。本地私网候选、mDNS名称、递归 DNS和公网出口分别解释。

不支持某类 UDP的节点可能使流量跳过预期规则。明确拒绝或实测该协议经允许出口，不能为恢复连通添加直连。调整 QUIC或实时音视频策略时说明功能影响。

## 交付

逐项标为实测通过、配置已验证、未测、存在缺口。写明进程/执行边界、窗口、样本、正控制、丢失情况、故障层级及恢复结果。历史回执、未观察到连接、静态字符串搜索都不是永久保证。
